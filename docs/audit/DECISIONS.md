## Review pass before the first commit (2026-09-24)

Eight review angles ran over the whole codebase (correctness, invariants, cross-file tracing, reuse, simplification, efficiency, altitude, conventions). Applied: the daemon's live pid always wins in `daemon.json`; entries without a PR are never looked up; the event cursor starts at the PR's creation so a review that lands during the start run is seen, and inline comments are fetched from the earlier of the two windows; a separate `checks_sha` cursor so red CI on the loop's own pushes is dispatched, with `checks-red` when it stays red; `fixed_sha` is snapshotted at dispatch so a run that did not push is never counted as a round; a fresh session id is allocated for registered PRs; receipt-only rounds and resets post marked comments so the count rebuilt from GitHub matches; the PRD is read from the daemon's own snapshot, never from the agent-writable checkout, and the block rejects `..` paths; the repo comes from GitHub's canonical URL and ids include the owner on collision; `ready` is local-only without a config and no longer commits; the worktrees check compares path segments; `#` lines inside fenced blocks are not headings; one config merge for `load` and `doctor`; one parser each for the mode file and the audit log; one `execFile` wrapper with timeouts for `gh` and `git`; the diff is scanned by the completion gate; dead exports removed. Deferred as efficiency work: skipping the three REST fetches when the PR's `updatedAt` has not moved, probe caching, and a bounded concurrency across entries.

## Second review pass, over the fixes (2026-09-24)

The same eight angles ran again over the code after the first pass, because a fix regresses as easily as a feature. Every item below is fixed with a test in `test/`; the suite is 76 tests.

Correctness. After a pushed fix run the event cursor is the push's commit time from GitHub, not the settle time, so a review that landed while the run was finishing is dispatched (settle time is the fallback). A reviewer that blocked a head before the cursor no longer leaves the entry waiting forever: `reviewer-blocking`, once per head. The "edited comment" heuristic is gone; a comment is new when it was created after the cursor, and editing it later neither hides it nor dispatches it twice. Liveness asks whether the pid still runs the harness binary, so after a daemon crash a reused pid is not killed or counted as a run. The registry holds a lock file around every read-modify-write, so the CLI and the daemon cannot lose each other's writes. An empty check list on a head younger than `checks_grace_minutes` is "not reported yet", not green; when GitHub cannot date the head the window counts from the recorded push time so a repository without CI still becomes ready. `settleRun` only settles the run the entry dispatched (`last.run`), so a reset or a recovery never re-settles a leftover run as `no-push`. The completion gate scans only added diff lines. `gh api --paginate` now passes `--slurp`, so a PR with more than a hundred comments parses. Deny messages from the gate carry PR-body text and are quoted like everything else from GitHub. An unreachable APort is "no decision" by default: nothing dispatched, no round counted, tried again next tick (`deliverable.on_unreachable`). The daemon loop catches every tick failure; a harness binary that cannot start is recorded as exit 127 on that run; a death by signal is recorded with the signal; the log file descriptor is closed when the run ends. `why` prints `claude --resume <id>`. A signed-out harness makes `start` fail with the fix instead of recording a placeholder entry; `remove` forgets an entry. Recovery from GitHub takes the PRD snapshot from the PR branch when the daemon has none and says so in the log. The daemon's own round and nudge comments are checked for before posting, so a tick interrupted between the comment and the save does not post twice.

Reuse and shape. One `alive`, one token reader, one fence grammar (`fencedBlocks`, `withoutFences`), one branch convention (`branchFor`, `isOurBranch`, `prdIdFromBranch`), one worktree recreate, one `fixOrStop`, one `commentOnce`; `entryId` is a pure function of repo and PRD and every path keyed by it uses `idSlug`; `withFrontmatterKey` rebuilds from the parsed block; the receipt denial is a prompt argument instead of a synthetic event; the config `reviewer` merge line that implied deep merge is gone; labels are created once per repo; `whence` is memoised; `ready` decides locally only when there is no config, and fails on an invalid one; the PRD is parsed once per tick; entries tick four at a time.

Not changed, on purpose. Probes still run every tick (they are how a sign-out is noticed within one poll). `state.json` is still re-read per accessor; it is small and the lock makes the reads consistent.

15. Hosted passport presets set `max_execution_time` (900 in the Claude Code preset) while Codex's `exec_command` is unbounded by design, so under that preset every Codex exec is denied once the hook stops fabricating timeout evidence. The policy is doing what it says. The preset should either omit `max_execution_time` for frameworks whose tools have no bound, or the policy should gain an explicit `allow_unbounded` limit. Until then an operator on Codex should remove `max_execution_time` from the hosted passport. (agent-passport)
